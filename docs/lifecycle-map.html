Closing the loop: raia agents inside the AI development lifecycle

raia holds the organization's knowledge and talks to everyone. Claude Code holds the repository and ships the code. The AI DLC is what happens when the two are wired together — so product knowledge flows into every coding session, and everything shipped flows back into the agents' training.

01 · The thesis

Two complementary systems, one missing loop

Centralized knowledge & conversation

raia

  • raia Command — ingest thousands of documents, chunk, embed, train vector stores; connectors to SharePoint, Drive, and more
  • raia cX + Launch Pad — build role-specific agents with instructions, skills, guardrails, and the Orchestrator for multi-agent routing
  • raia Copilot — human-in-the-loop UI: Admin Mode, simulations, takeover, feedback and scoring
  • Access anywhere — MCP server mode, MCP client mode, REST API, n8n node, browser extension, Teams, chat/SMS/voice
Repo-native execution

Claude Code

  • Reads and writes the actual codebase — plans, implements, tests, reviews, opens PRs, babysits CI
  • MCP client — connects to any MCP server, including raia's, per-repo via a committed .mcp.json
  • Skills & hooks — repeatable team workflows (/security-review, custom skills) and lifecycle hooks for automation
  • Runs headless — GitHub Actions, web sessions, and scheduled routines, not just a terminal
The missing loop: today, what the PM knows lives in raia's vector stores, and what the codebase knows lives in git. Neither system learns from the other automatically. The integration goal is a closed circuit — agents brief the code, and the code retrains the agents.

PM · async oversight

Asks their agent "what's the status of the checkout feature?" — via MCP client mode the agent reads GitHub PRs and the tracker, and answers in plain language inside Copilot, Teams, or the browser extension.

Dev · Claude Code

Implements with raia tools live in-session: run_prompt to ask a knowledge agent mid-task, get_prompt_response for API-contract questions, project skills for repeatable jobs.

Edge-case question? Ask the Support Agent how customers actually hit this path.

PM · raia Copilot simulations

For agent-facing features, runs Copilot simulations against a staging agent before launch — the product equivalent of a test suite, no code required. Feedback ratings become structured QA data.

5
Verify
Both sides test in their own language
Dev · Claude Code review

Runs /code-review and /security-review; a review skill can also check the diff against the spec by querying the Product Agent — "does this match the agreed refund policy behavior?"

PM · zero-lag enablement

The moment the release merges, the Support Agent and Product Agent already know about it. No "update the help center" backlog; support answers reflect the new behavior on day one.

6
Ship
Merge = retrain
Dev · CI post-merge hook

CI generates release notes and updated docs, then calls add_agent_file_to_vector_store to push them into raia Command. One API call closes the loop — the org's agents are never behind the codebase.

PM · Copilot analytics

Watches how the shipped feature performs in real conversations — feedback scores, escalation rates, Control campaign engagement. Signals that regress become next cycle's Discover input.

7
Learn
Usage becomes the next backlog
Dev · scheduled routine

A weekly headless Claude Code routine queries the Support Agent for new error patterns, cross-references Sentry and the repo, and files pre-investigated issues. The cycle restarts at phase 1 — with better inputs than last time.

04 · Integration patterns

Five wiring patterns, from live-today to ambitious

Pattern A · Knowledge pull works today

raia agents as MCP tools inside Claude Code

raia's MCP server mode exposes any agent as a callable tool. Commit an .mcp.json to each repo so every developer's session — terminal or web — starts with the Codebase and Product agents connected. This very session has them live.

Claude Code ──ask──▶ raia MCP server ──RAG──▶ vector store ──answer──▶ session context
Pattern B · Knowledge push works today

CI retrains agents on every merge

A post-merge job converts changed docs to Markdown (raia's own convert tool helps) and pushes them to the agent's vector store via the REST API. Docs, ADRs, release notes, OpenAPI diffs — all become agent knowledge automatically.

merge → CI ──md──▶ add_agent_file_to_vector_store ──▶ raia Command ──▶ agents updated
Pattern C · PM visibility

raia agents read the dev toolchain

raia's MCP client mode connects an agent to GitHub and Jira MCP servers. PMs ask status questions in Copilot, Teams, or the browser extension and get answers grounded in live PRs and tickets — no standup required, no GitHub login required.

PM in Copilot ──ask──▶ agent ──MCP──▶ GitHub / Jira ──▶ plain-language status
Pattern D · Event-driven pipeline

Customer signal to pre-triaged branch

A bug reported in raia Chat triggers an n8n flow: a triage agent extracts reproduction steps and severity, files a GitHub issue, and for well-scoped bugs a headless Claude Code session picks it up and opens a draft PR before a human ever looks.

Live Chat ─▶ triage agent ─▶ n8n ─▶ GitHub issue ─▶ Claude Code session ─▶ draft PR
Pattern E · Spec-aware review

The Product Agent sits in code review

A custom review skill queries the Product Agent with the diff's behavioral changes: does this match the spec, the compliance rules, the promised copy? Combines with raia's Auditor Skill for PII and policy checks on agent-facing changes.

/review skill ──diff summary──▶ Product Agent ──spec check──▶ PR comment
